Student Academic Performance Prediction using Machine Learning

"Educational institutions often struggle to identify academically at-risk students in advance. This project uses a dual-model XGBoost pipeline to predict student performance — one for early intervention (before exams) and another for high-accuracy forecasting (with interim grades)."

Problem Statement

Institutions cannot predict student performance early or identify academically at-risk students in advance. This project builds a data-driven machine learning pipeline — powered by XGBoost — to help teachers recognize performance trends, identify at-risk students, and intervene in time to improve overall academic outcomes.

Literature Review / Market Research

  • Akter et al. (2025): Used Explainable AI to analyze academic factors. Limitation: Focused mainly on exam-based evaluation.
  • Rohani et al. (2024): Applied ClickTree model on digital engagement data. Limitation: Restricted to e-learning environments.
  • Thakar et al. (2024): Developed a combined machine-learning model to predict employability and academic readiness. Limitation: More suitable for employability studies rather than school-level analysis.
  • Darshini (2024): Examined academic, personal and family-related variables to analyse their influence on student outcomes. Limitation: Does not include practical improvement strategies.
  • Kumar & Behera (2023): Applied models like Random Forest and SVM to identify academically at-risk learners. Limitation: Dataset size and diversity are limited.

Research Gap / Innovation

  • Dual-Model Pipeline: Unlike single-model approaches, this project deploys two specialized XGBoost models — a Holistic model for early-semester risk detection and a Grade-Based model for high-accuracy mid-semester predictions.
  • Actionable Insights: Goes beyond prediction to offer teachers specific guidance for early intervention and improved learning support.
  • Production-Ready API: Includes a Flask-based REST API with schema validation, error handling, and live prediction endpoints.

System Methodology

1. Data Collection

UCI Repository — 395 records, 33 features covering academics, demographics & behavior.

2. Preprocessing

Label-encoded categoricals, handled missing values, removed irrelevant features, 80-20 train-test split.

3. Model Training

Trained 5 models: Linear Regression, Decision Tree, Random Forest, XGBoost (Holistic), XGBoost (Grade).

4. Deployment

Flask REST API with /predict, /schema, and /health endpoints.

Dataset Source

UCI Machine Learning Repository — student-mat.csv

395 students × 33 attributes including study time, attendance, family background, and interim grades (G1, G2).

Features Used

  • Demographics: age, address, family size
  • Family: parents' education & jobs
  • Lifestyle: study time, free time, alcohol
  • Academic: absences, failures, G1, G2

Preprocessing

  • Categorical → Label Encoding
  • Missing value imputation
  • Feature selection (removed noise)
  • 80-20 stratified train/test split

Dual-Model Architecture

Our innovation: two specialized XGBoost models serving different stages of the academic cycle.

Holistic Model

Early Warning System

Inputs: Lifestyle & demographics ONLY — no exam scores (G1, G2).

Use Case: Counselors use it on Day 1 of the semester to flag at-risk students.

Performance: R² ≈ 0.29 — lower accuracy but provides actionable early insight.

R² Score

0.29

Grade-Based Model

High-Accuracy Forecasting

Inputs: Lifestyle + Interim Grades (G1, G2).

Use Case: Final grade projections midway through the year.

Performance: R² ≈ 0.77 (XGBoost) to 0.81 (Random Forest) — high-accuracy prediction.

0.77

Engineering Journey

The evolution from over-engineered complexity to clean, production-ready simplicity.

Phase 1

Over-Engineering

Initial attempts with K-Means Clustering and heavy feature engineering caused R² to drop from 0.29 → 0.21. On a 395-row dataset, complexity added noise.

Phase 2

Simplification

Removed clustering, focused on raw high-value behavioral features, and stabilized XGBoost hyperparameters for small-data robustness.

Phase 3

Dual-Model Architecture

Split into two workflows: Holistic (early warning, no grades) and Grade-Based (high accuracy, with G1/G2).
